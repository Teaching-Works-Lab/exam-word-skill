# 试卷生成踩坑清单与验收门禁

> **Exam Authoring Pitfalls & Acceptance Gates**
>
> **何时必读**：任务不是「把已有 Word/PDF 套模板」，而是**从题库 / 大纲 / 知识点出一份新卷、重组 A/B 卷、或调整既有试卷的题型与分值**时。本文件与 `modes.md`、`template-contract.md` 同为必读。
>
> **来源**：2026-11《智能制造装备》期末 A/B 卷实战复盘（三轮修订）。下面每一条都对应一次实际返工，不是理论推演。

## 0. 一条原则

> 结构化 JSON 是唯一内容源；DOCX 只是模板渲染结果；**只通过 OOXML 结构校验不算验收，必须渲染成 PDF 逐页检查分页**。

`verify_docx.py` 只能证明模板部件未被破坏，它**不会**发现「选项被分页拦腰截断」「题干半句跑到下一页」「（15 分）被拆成孤立的『分）』」。这类问题只有渲染后才可见。

## 1. 内容来源与方案对齐

| 坑 | 必做 |
|---|---|
| 误以为仓库里有现成试题 | `assets/reference.docx` 只是**格式模板**，仓库不存题目。题目来自用户题库 / 大纲 / 知识点，必须在对齐稿里写明真实来源 |
| 接到「出份试卷」就直接出终稿 | 先出**试卷明细对齐稿**让用户确认：考试性质（期末笔试 / 考查）、题型结构、各部分分值、卷数（A 卷 / A+B 卷）、是否含主观题 |
| 大纲考核方式与用户要求冲突 | 大纲写「考查」（无笔试）而用户要「期末笔试」时**明确提示**，并建议在课程考核方案里补一条笔试说明；不要默默改 |
| 卷头信息是占位值 | `school` / `academic_term` / `unit` / `teacher` / `exam_mode` / 考试时长都是占位值，交付时必须请用户确认，或在回复里显式标注 |
| 某教学单元题库 0 题 | 按大纲**新编**并在明细里逐题标「新编」，便于教师重点审核；不要跳过该单元 |
| 用户临时调整分值结构 | 客观题压缩后，被砍下的题不要丢：与题库余量重组为 B 卷，并校验 A/B **客观题、主观题均零重复** |

**方案对齐前不要调用 `build_from_spec.py`。** 对齐稿里应包含：依据材料、题库盘点、卷面结构表、逐题明细、单元/课程目标覆盖、待确认事项。

## 2. 题库清洗（生成前，不是生成后）

题库抓回来先做**全库过滤**，再抽题。真实案例：题库 453 题中 #249 是残题——题干混入整段方案描述、选项只剩 `A. 点移到` / `B. 点，无需毫米级精度)`、答案为空；它混进卷面后变成「第 8 题数据异常」。

```python
def bad(x):
    ans = (x['answer'] or '').strip()
    opts = [o for o in x['options'] if o.strip()]
    if x['type'] == '单选题':
        if len(opts) < 3: return '选项不足'
        if not re.fullmatch(r'[A-E]', ans): return '答案异常'
    elif x['type'] == '多选题':
        if len(opts) < 3: return '选项不足'
        if not re.fullmatch(r'[A-E]{2,5}', ans): return '答案异常'
    else:  # 判断题
        if ans not in ('正确', '错误'): return '答案异常'
    if len(x['stem'].strip()) < 8: return '题干过短'
    return None
```

还要做三项**体检并如实报告**：

1. **答案分布**：单选题若某个字母占比过高（实测 B 占 10/18 = 56%、D 为 0 道）、多选出现全选 `ABCD`，要提示用户。**不要擅自打乱选项**——重排后卷面答案字母会与平台上原题对不上；若要打散，用「循环移位」保留选项相对顺序，并说明题库序号对应关系随之失效。
2. **单元权重对照大纲**：新编热点题天然集中在某几个单元，容易把权重拉偏。明细里必须列出「大纲权重 vs 卷面实际」，偏差如实标注。
3. **答案隔离**：学生卷不得出现 `答案：` / `参考答案` / `评分要点` / `正确答案` 等字样；参考答案与评分标准**单独成文件**。

## 3. 得分表：分数行、得分行必须留空

> **与直觉相反**：卷首得分表是**阅卷教师填写并签字**用的，不是印给学生看的分值表。

- `score_table` 只填第一行「题号 / 一 二 三 四 五 / 总分」；**「分数」行和「得分」行（含总分格）全部传空串**。
- 各大题分值改印在**大题标题**里，例如 `四、简答题（共 4 题，每题 10 分，共 40 分）`，学生照样看得见分值。
- `metadata.summary` 仍可写「满分 100 分；考试时间 120 分钟」。

```json
"score_table": [
  ["题号", "一", "二", "三", "四", "五", "", "总分"],
  ["分数", "", "", "", "", "", "", ""],
  ["得分", "", "", "", "", "", "", ""]
]
```

`_populate_score_table()` 会把未指定的单元格清空，所以**不传 `score_table` 也会清空**；但显式传空串更不容易被模板里的旧值误导。注意 `modes.md` 与早期测试里的 `["分数","40","60","100"]` 只是验证 builder 行为的样例，**不是命题规范**。

## 4. 分页与段落控制（最容易返工的一节）

### 4.1 spec 段落控制字段

`build_from_spec.py` 的 `_configure_paragraph()` 支持以下可选字段（**`modes.md` 早期版本未记录**）：

| 字段 | 作用 | 典型值 |
|---|---|---|
| `keep_next` | 与下一段同页（`w:keepNext`） | `true` |
| `keep_together` | 段内不分页（`w:keepLines`），防长题干半句跨页 | `true` |
| `left_twips` | 整段左缩进（twips） | `question` 默认 283，`option` 默认 425 |
| `first_twips` | 首行相对缩进（负值 = 悬挂） | `question` 默认 -283 |
| `before_pt` / `after_pt` / `line_pt` | 段前 / 段后 / 行距 | `spacer` 用 `after_pt` 撑答题空白 |
| `align` | `left` / `center` / `right` | — |

`_add_block()` 里 `question` 默认 `{left_twips: 283, first_twips: -283}`（题号顶格、正文从 283 起），`option` 默认 `{left_twips: 425}`。**block 自带同名字段会覆盖默认值**，这正是做小问缩进的入口。

### 4.2 断页三条规则

1. **一道题不可分割**：题干加 `keep_next`，除**最后一个选项外**所有 `option` 加 `keep_next`，使「题干 + 全部选项」成为同页块。否则会出现第 1 页题干 + 前两个选项、第 2 页页首孤零零 `C.` / `D.`。
2. **判断题是例外**：判断题**没有选项**，若给题干加 `keep_next`，14 道题会连锁绑成一大块，反而制造大片留白。判断题只加 `keep_together`。
3. **长题干段内不分页**：多行题干要加 `keep_together`，否则会出现「…铣削」在第 5 页末、「)。( )」在第 6 页首。

### 4.3 中文断行与分值残片

- 题干末尾的 `（15 分）` 会被中文断行拆成「（15」+「分）」，在页底留下孤立残片。**不要**在题干里重复写分值——大题标题已声明，直接从源数据删掉。
- 若确实需要保留分值标注，用不换行空格 `\u00a0` 连接数字与「分」；根治办法仍是删除冗余标注。

### 4.4 小问必须逐行显示

`（1）…（4）`、`①…⑤` 这类编号小问**不能挤在一个段落里**，教师要的是「一行一个小问、有缩进、与题干对齐、看着舒服」。

```python
ITEM_MARK = re.compile(r'（\d+）|[①②③④⑤⑥⑦⑧⑨⑩]')

def split_items(text):
    marks = [m.start() for m in ITEM_MARK.finditer(text)]
    if not marks:
        return [text.strip()]
    parts = []
    if marks[0] > 0:
        parts.append(text[:marks[0]].strip())
    for i, st in enumerate(marks):
        en = marks[i + 1] if i + 1 < len(marks) else len(text)
        parts.append(text[st:en].strip())
    return [p for p in parts if p]
```

要点：

- 只认**纯数字括号编号**与圈号；`（各至少 3 点）`、`（至少 4 类）`、`（喷嘴/热床温度…）` 这类说明括号**不能误拆**。
- 引导句（「请完成：」）单独一段，加 `keep_next` 绑定第 1 小问。
- 每个小问一个独立 `question` block，带 **`left_twips: 425, first_twips: -142`**：首行起点 `425-142=283` 与题干正文对齐（不顶格），回行从 425 起形成悬挂缩进。
- 各小问加 `keep_together`（段内不分页）；**中间小问不要加 `keep_next`**（会连锁造成留白）；最后一个小问加 `keep_next` 绑定答题空白。
- 试卷明细 Markdown 同步一行一个小问（用全角空格缩进），与卷面保持一致。

### 4.5 显式分页与答题空白

- `pages[]` 每多一项就插入一个硬分页符。**不要按题目逐条分页**：客观题连续排版让其自然流动，按题型分块即可（实测 5 个 spec page 得到 7 个物理页，比 10 个硬分页干净）。
- 答题空白用 `{"type":"spacer","text":"","after_pt":N}`。**小问拆行后题干占高增加，必须同步收敛 `after_pt`**（例：简答 200→190、综合 480→420），否则整块连同空白会被挤到下一页。
- 拆行后总页数、断页数要重新检测，不能沿用上一版结论。

## 5. 渲染验收（不可跳过）

按顺序执行，任一步失败都要回到 spec 重排：

1. `python scripts/verify_docx.py <out.docx> assets/reference.docx` → `valid: true` 且 `preserved_parts_match: true`。
2. **内容门禁**（按 spec 逐条比对 DOCX 段落文本）：题干数、选项数零缺失；得分表数值全空；无答案泄漏关键词；无 AI 生成痕迹（注意「大语言模型」是**题目内容**不是生成痕迹，别误报）。
3. LibreOffice 渲染 PDF → PyMuPDF 逐页提取文本：
   - 页首是否为孤立选项行 `^[A-E][\.、．]`（应为 0 页）
   - 题干是否跨页断裂（页首残句是某题干的尾部，应为 0 处）
   - 页末是否有长度 ≤4 的残片（「分）」「行」）
   - 页首是否为孤立小问编号
   - **过滤页脚**（`第 N 页 / 共 N 页`）后再判断正文首行
4. 渲染关键页 PNG 做视觉复核：卷头、得分表、小问逐行排版、答题空白是否充足。
5. 交付前确认：A/B 卷题目零重复；明细答案序列与试卷逐题一致；单元权重与大纲对照已标注。

## 6. 常见诱惑 → 必选动作

| Temptation | Required choice |
|---|---|
| 只跑 `verify_docx.py` 就交付 | 渲染 PDF + 逐页断页检测 + PNG 视觉复核 |

| 题库直接抽题不看质量 | 先全库过滤残题，再体检答案分布与单元权重 |
| 发现答案分布偏斜就打乱选项 | 先报告用户；重排会破坏与平台原题的对应 |
| 只改 DOCX 不回写 spec | spec 是唯一内容源，所有改动在 spec/生成器里做 |

## 8. A/B 平行卷去重（双卷场景，2026-11-24 新增）

平行卷只做到「题干不完全相同」是不够的。同一门课、同一份大纲，考点必然有交集；真正要拦的是三种重复：**同一道题换种说法**、**参考答案可以互相套用**、**两卷压在同样两个单元**。

### 8.1 检查项与阈值

| 层级 | 检查 | 阈值 | 为什么 |
|---|---|---|---|
| 题干 | 精确相同（去空白 / 标点后） | 0 容忍 | 直接泄题 |
| 题干 | 近似相似度（`difflib`） | < 0.60 | 防「换种说法」 |
| 选项 | 选项组合完全相同 | 0 容忍 | 改题干不改选项 = 同题 |
| 答案 | 客观题答案序列完全相同 | 0 容忍 | 序列雷同，蒙题有规律 |
| 主观题 | **参考答案**相似度 | **< 0.35** | 最关键：背一套答案不能通吃两卷 |
| 主观题 | 题干相似度 | < 0.60 | 同上 |
| 单卷 | 卷内重复 | 0 容忍 | 本卷自己的低级错误 |

### 8.2 门禁代码（放在组卷脚本末尾、构建 DOCX 之前）

```python
import difflib, html, re

def _n(s):
    return re.sub(r'[\s，。、（）()：:；;「」『』【】,.]', '', html.unescape(s or ''))

def _sim(a, b):
    return difflib.SequenceMatcher(None, _n(a), _n(b)).ratio()

STEM_LIMIT, ANSWER_LIMIT = 0.60, 0.35

for a in obj_a:
    for b in obj_b:
        assert _n(a['stem']) != _n(b['stem']), '客观题题干重复'
        assert _sim(a['stem'], b['stem']) < STEM_LIMIT, '客观题题干近似重复'
assert set(tuple(q['options']) for q in obj_a if q['options']).isdisjoint(
       set(tuple(q['options']) for q in obj_b if q['options'])), '选项组合重复'
assert ' '.join(x['answer'] for x in obj_a) != ' '.join(x['answer'] for x in obj_b), '答案序列相同'

max_ans = max(_sim(a['answer'], b['answer']) for a in SUBJ_A for b in SUBJ_B)
assert max_ans < ANSWER_LIMIT, f'主观题参考答案可套用（{max_ans:.2f}）'
```

门禁必须打印量化结果留档，否则「零重复」只是一句口头承诺：

```text
[去重门禁] 客观题 18×18 对：题干/答案序列/选项组合 0 重复
[去重门禁] 主观题 6×6 对：题干最高相似 0.19｜参考答案最高相似 0.16
```

### 8.3 最容易漏的三类「软重复」

1. **综合应用题同题化**：两卷综合题都写「某设备采集多源数据，请设计诊断流程」，参考答案都会落到特征工程、混淆矩阵、迁移学习、模型漂移、可解释性——文本相似度可能只有 0.38，但**考点是同一套**，学生背一份要点即可通吃。处理：两卷综合题换**不同装备载体 + 不同命题角度**（如 A 卷「FDM 工艺质量追溯」、B 卷「数控机床精度与热误差伺服」）。
2. **多选题引导句撞车**：两道多选都写「关于 X，下列说法正确的有（ ）」，`difflib` 会给到 0.5+。这不是重复，但会让人误判、也让门禁数字难看。处理：换引导句式（「下列判断合理的有」「在……场景中，下列做法恰当的有」）。
3. **热点题两卷各来一套**：大模型、数字孪生、PHM 在两卷都出主观题，答案必然高度重合。处理：热点**分工**——A 卷主观题走新技术（大模型 / 孪生 / PHM），B 卷主观题走装备本体与控制（精度 / 伺服 / 柔性 / 信号链），热点通过**客观题**在两卷都保留。

### 8.4 改完 B 卷要复查的三件事

- 单元分值分布会变（组卷脚本自动重算），确认两卷**互补覆盖**六单元，而不是某单元两卷都为零；
- 明细里的「单元与课程目标覆盖」表和「分布提示」要随新题自动更新，不要留旧结论；
- 参考答案必须与卷面**同源重生成**，不能只改卷不改答案。

## 9. 程序代码类试卷专项规范（2026-11-24《程序设计基础（C&C++）Ⅰ》期末 A/B 卷复盘）

> **何时必读**：试卷含程序阅读、查错与测试、代码填空、代码片段选项等**多行代码**时。
> §1~§8 的通用规则继续生效；下面每一条都对应一次真实返工，不是理论推演。
> **来源**：C&C++ Ⅰ 期末 A/B 卷四轮卷面修订 + 重复率量化检查。

### 9.0 一句话结论

代码类试卷**不要直接用 `build_from_spec.py`**：它不支持 `code` block，也不支持「一题一行不拆页」。
用已固化的 `scripts/build_code_exam.py`（见 §9.5），并把 §9.1~§9.7 当作出卷前的硬门禁。

### 9.1 卷面与题号

| 坑 | 必做 |
|---|---|
| 卷面印出 `A9+A10`、`9A+10A` 之类标记 | 学生看不懂内部关卡/知识点编号，**卷面一律删除**；命题编号只留在教师用明细与答案文件里 |
| 全卷连编 `T1~T33` | 题号**按每道大题各自从 1 开始**（本次 10/5/10/4/2/2）；答案文件加「卷面题号 ↔ 命题编号」对照表 |
| 题干过长把句末「（3 分）。」折到下一行 | 压短题干；答题说明压成一行放在得分表下方 |
| 判断题的「（　）」变成孤行 | 缩短表述或调整排版，卷面不留孤立符号 |
| 手动硬分页 | 改**自然分页 + 压缩间距**。硬分页与内容溢出叠加会碎片化（实测 9 页 → 6 页） |

### 9.2 分值与得分标注（教师明确点名「得分的位置」）

- 小分**一律整数**、**句末后置**，`……（4 分）`。禁止 `4.5 / 2.5 / 1.25 / 0.75` 等小数，禁止把分值前置或写在题干开头。
- **答案与评分细则必须同步**改成整数分配（例：T30「指出 bug 4 分 / 测试用例 3 分」），不允许卷面与答案分值不一致。
- 卷首得分表「分数」「得分」行全空（§3），各大题分值印在**大题标题**里。
- 分值不要重复标注：大题标题已声明，题干末尾不再写，否则中文断行会拆出「（15」+「分）」残片（§4.3）。

### 9.3 程序代码书写规范（教师明确点名「程序不美观」）

- 必须是**可编译、真实完整的 C 程序**：`#include <stdio.h>`、`int main(void)`、`return 0;`；不要只贴片段，不要顶头直接写语句。
- 4 空格缩进；`struct` 展开成多行；`#define` 单独成行；函数之间空行；注释右对齐；长 `printf` 手动拆行控宽度。
- 代码块整体**左缩进**（425 twips），不顶头。
- **无边框**（`Normal Table`，不要用 `Table Grid`，否则出现黑框）、**无行号**。
- 字体：ascii/hAnsi/cs = Consolas，eastAsia = 宋体，9.5pt / 固定行距 12.5pt。
- 交付前**全文扫描 HTML 转义残留**：代码里的 `<<`、`&` 常被写成 `&lt;&lt;`、`&amp;`，会直接印错在卷面上。

### 9.4 命题质量：选项与题型

- 选择题各选项**长度与信息量做平**。某选项明显更长、信息更多，学生靠长短就能猜答案 → 本题作废重出（本次 T9 因此重出）。
- 主观性判断（「哪条提示词更好」）不要放单选题，除非题干给**具体场景**使其客观化。本次改为「8051 单片机 LED C 程序，提示词必须写明目标芯片型号与运行环境」，答案 B。
- 长选项两选项一行；tab 位放宽（两列 3.40"、四列 1.75/3.50/5.25"）、字号 11pt，避免两列挤在一起。

### 9.5 代码与整题不拆页的可靠渲染架构（最容易返工的一节）

三次演进，前两次都失败：

1. 逐行段落 + `keep_with_next` 长链 → **LibreOffice 会忽略长链**，代码被劈页。
2. 1×1 无边框表格 + 行 `cantSplit` → 代码块自身不拆页了，但 `keep_with_next` **对表格无效**，出现「代码块与其后选项分家」。
3. 整题 `keep_with_next` 推页 → 某题放不下就整题推到下一页，页尾留大片空白。

**最终方案（已固化为 `scripts/build_code_exam.py`）**：一道大题一张无边框表格、**一道题一行、行内 `cantSplit`**。

- 行内不跨页：题干 + 代码 + 选项 + 小问永远在同一页；
- 行间允许跨页：不会因某题放不下就在页尾留大片空白；
- `cellMar=0`、`tblInd=0`；单元格内段落缩进沿用 283 / 425 / 567；题间距用首段 `before=6`；
- 文档**不能以表格结尾**，末尾补一个 1pt 极小空段；
- 复用 `build_from_spec.py` 的 `_clear_body` / `_add_header` / `_populate_score_table` / `_restore_parts`，保证 7 个保留部件 byte-identical、`verify_docx.py` 仍通过。

关键 OOXML：

```python
tbl.style = "Normal Table"
tblPr.append(OxmlElement("w:tblInd"))       # w=0
tblPr.append(OxmlElement("w:tblCellMar"))   # 四边 w=0
for row in tbl.rows:
    row._tr.get_or_add_trPr().append(OxmlElement("w:cantSplit"))
```

spec 在通用契约之上新增两种 block：

```json
{"type": "code", "lines": ["#include <stdio.h>", "int main(void) {", "..."]}
{"type": "option-row", "items": ["A. ...", "B. ..."]}
```

命令：`python scripts/build_code_exam.py spec.json out.docx`（可传第三个参数指定模板）。
生成后**仍须走 §5 全套门禁**：`verify_docx.py` → 内容检查 → LibreOffice 渲染 PDF → 逐页断页检测 → PNG 视觉复核。

### 9.6 A/B 卷重复率：量化口径与答案错开（补 §8）

§8 给的是「零容忍」判据；代码类试卷还要出**量化报告**留档，不能只说「零重复」：

- 指标：题干 `SequenceMatcher` 相似度、代码 Jaccard、字符 5-gram 全卷重合率、最长公共片段、代码逐字相同行数；
- 阈值：文本 ≥ 0.85 或代码 ≥ 0.60 判重复，0.70~0.85 需人工复核；
- **固定题型提示语也会拉高相似度**（「运行下列代码，输出结果是」这类句式），两卷要换句式、换阅读题问法、换引导句，而不只是换数据；
- **答案位置刻意错开**：客观题答案序列不全同、多选组合全不同、判断正误分布不同；
- 本次实测留档：文本均值 0.406 / 最高 0.650，代码均值 0.018，5-gram 6.4%，最长公共片段 8 字，代码逐字相同 7/71 行（9.9%）→ 0 道实质重复、0 道需复核、33 道通过。

### 9.7 同源与交付自检增补

- 试卷 Markdown / DOCX / 答案与评分细则由**同一份结构化 JSON + 同一生成器**产出，禁止手改 DOCX；B 卷答案解析必须与卷面同源同步更新。
- 答案文件加「卷面题号 ↔ 命题编号」对照表。
- 卷头 `school` / `academic_term` / `unit` / `teacher` 是占位值，交付时显式请用户确认（§1）。
- 在 §7 自检清单上追加：

  - [ ] 卷面无内部关卡编号；题号按每道大题各自从 1 开始
  - [ ] 分值全为整数、句末后置，答案已同步
  - [ ] 代码完整可编译、有缩进、无黑框、无行号、无转义残留
  - [ ] 代码 / 选项 / 题干零跨页，页尾无大片空白
  - [ ] 选项长度与信息量做平；单选题无主观判断
  - [ ] A/B 重复率量化报告已留档，答案位置错开
  - [ ] 自然分页，总页数与答题空白已复核

## 10. 答案卷 / 评分细则标准卷（2026-11-24 新增）

> **何时必读**：要交付「参考答案与评分细则」「客观题答案速查」「A/B 卷答案对照」的 Word / PDF，而不只是 Markdown 时。

### 10.1 答案卷不是「试卷换个内容」

> **适用范围（2026-11-24 修订）**：本节只约束**教师答案册**（`answer-booklet`，显式 opt-in）。默认「答案」产出的是卷面标注答案卷，恰恰是「试卷换个内容」，见 §11；**不要拿本节的规则去判默认答案卷**。

学生卷的三件套——学号/姓名栏、卷首得分表、答题空白——教师答案册一件都不需要：留着会让人误以为是学生卷，留白纯属浪费版面。教师答案册是**另一套版式**，用 `scripts/build_answer_docx.py`，不要复用 `build_code_exam.py`。

### 10.2 教师卷头：四行，且不要用 tab 定位

| 行 | 内容 | 格式 |
|---|---|---|
| 1 | 学校名 | 居中、加粗、16pt |
| 2 | 学期　命题单位：X　命题教师：Y | 10.5pt，**全角空格串联** |
| 3 | 【课程】课程　（A 卷） | 课程名与「课程」加粗 |
| 4 | 参考答案与评分细则 · 教师用（请勿下发给学生） | 居中、加粗、11pt |

下面再跟一行灰色 summary（题量 / 满分 / 包含哪些部分）。

**为什么不设 tab**：学院名一长（如「计算机与信息技术学院」），`6.3"` 的右 tab 位就超出正文宽度，「命题教师：姜启龙」会被挤到页外、只剩「命题教师：」。实测踩过。改成全角空格后不再溢出。

也**不要靠 `Heading 1/2` 样式字号**撑卷头：模板的 Heading 字号偏大，长行同样会撑爆。显式设字号更可控。

同时**删除**：序号/学号/姓名/专业及班级栏、卷首得分表。

### 10.3 内容门禁

- 保留「卷面题号 ↔ 命题编号」对照表（§9.1）；
- 客观题答案速查按**卷面位置**排；双栏速查表（8 列或 6 列）自动拆成左右两张，避免挤压折行；
- 主观题按小问列参考答案 + 评分细则，分值**整数、句末后置**（§9.2）；
- 代码块仍守 §9.3：无边框、无行号、Consolas + 宋体、左缩进 425 twips；
- **同源**：metadata 直接继承试卷 spec，只改 `paper` / `summary`；正文从同一份答案 Markdown 解析，不手抄。

### 10.4 分页与版心规则（答案卷允许自然跨页，但有六条底线）

1. 代码块、表格行各自 `cantSplit`；
2. 表格首行 `tblHeader`，跨页时重复表头；
3. 小表（≤ 8 行）除末行外全部 `keep_with_next`，整表不拆；
4. 「评分要点：」「测试用例（…）：」这类**标签行必须与紧随的表格 / 代码 / 要点列表同页**，否则会出现标题在页尾、内容在下一页。**无冒号的纯标签行（「参考答案」「评分要点」）同样要绑定**——它们后面跟的是 bullet 要点而不是表格，最容易漏。2026-11-24 实测 A 卷第 2 页末、B 卷第 3 页末各出现一次孤立「评分要点 / 参考答案」，内容整块翻页。
5. **表格总宽必须锁到正文宽**（`w:tblW type="dxa"`，各列 `gridCol` 之和 = 版心宽），不能交给 autofit 按最长单元格撑宽。一旦撑出版心，LibreOffice 会把紧随其后的段落可用宽度算成接近 0，整段变成每行一两个字。2026-11-24 实测：A/B 卷 5 列对照表溢出 10pt；A/B 答案对照表「主观题考点对照」后的说明段**整段竖排**。按内容长度分配列宽（权重 = 列内最长文本字数，下限 4）再锁总宽，既能自适应又不溢出。
6. 答案卷允许题目跨页，但「大题标题 → 参考答案标签 → 首条要点」必须同页（`keep_with_next`），避免标题孤零零留在页尾。

> **误判提醒 1**：页尾出现 2~3 字单独成行（如「案。」）通常是段落末行的中文断行，**不是**分页残片，不要为它返工。
> **误判提醒 2**：正文行末的中文标点（，；：）会悬挂在版心外约 10pt，PDF 测「文字最右」必然略超版心，这是正常中文排版，不是溢出。判断溢出要看**表格区域**，不是全页最右字符。

### 10.5 A/B 答案对照表：数字要算，不要抄

两卷答案要能「一眼对上」：逐位列出 `卷面位置 | A 卷答案 | B 卷答案 | 是否相同`，再按单选 / 多选 / 判断分别统计相同数。

**统计必须从两份答案文件解析计算**。本次实测：手工记成「判断 1/10 相同」与「3/10 相同」都出现过，脚本一跑才确认是 **1/25（判断仅三、5 相同）**。手抄必错。

### 10.6 交付自检

- [ ] 卷头四行完整、无溢出；无学号栏、无卷首得分表
- [ ] 答案速查表双栏拆分后不错行；表头加粗、跨页重复
- [ ] 代码块无边框无行号；标签与表格分页 0 处；页尾无孤立「参考答案 / 评分要点」标签行
- [ ] 表格总宽不超过版心；表格后的说明段未竖排（§10.4-5）
- [ ] 题号覆盖全部题目；分值整数、句末后置
- [ ] 无 AI 生成痕迹；`verify_docx.py` 返回 `valid: true`
- [ ] PDF 逐页复核，页数合理、无孤页（末页只剩 2~3 条说明即为孤页，需压缩排版）

## 11. 卷面标注式答案卷 与「人工另存」的契约边界（2026-11-24 复盘）

> **何时必读**：用户说「答案卷 / 标准答案 / 带答案的卷 / 评卷用卷」，或把一份自己手改过的 Word 拿回来说「照这个样式」时。

### 11.1 先分清三种形态，别默认答案卷只有一种

§10 覆盖的只是**独立教师答案册**。2026-11-24 用户把交付的《A卷-参考答案与评分细则.docx》整个重做成另一种形态，说明需求里还有第三类：

| 形态 | 典型叫法 | 卷头 | 题干 / 选项 | 得分表 | 答案放哪 |
|---|---|---|---|---|---|
| 学生卷 | 试卷、A/B 卷 | 学校 + 学号姓名栏 | 全量 | 有，分数/得分留空 | 无 |
| 教师答案册（§10） | 参考答案与评分细则、评分标准、教师用 | 四行教师卷头 | 不重印 | 无 | 速查表 + 逐题要点 |
| **卷面标注答案卷（本节）** | 答案卷、标准答案、带答案的卷、评卷卷 | **沿用学生卷**，卷别后加「答案」 | **全量重印** | **有，仍留空** | 客观题填题干括号；主观题题干后接要点 |

**默认答案 = 卷面标注答案卷（2026-11-24 起）**：用户只说「答案 / 参考答案 / 标准答案 / 评分标准」时，`route_request.py` 一律路由到 `answer-keyed-paper`，无需附件也能触发；教师答案册改为**显式 opt-in**（必须出现 教师用 / 答案册 / 评分细则 / 答案速查 / 对照表）。这是用户明确要求「以后说答案也会自动出来这个东西」后的定案。

冲突提醒：§10.1 写的是「答案卷不是试卷换个内容」，Common Drift 里也有「Reuse the student-paper layout for the answer key」。那条规则只对**教师答案册**成立；用户要卷面标注版时照 §10 做会被判成错件。**先按上表判形态，再选生成器；不要凭文件名里的「参考答案」四个字直接走 §10。**

### 11.2 从学生卷 spec 派生，别另起内容源

用户版实测指纹：卷头、得分表、24 道题的题干与选项、题号、小问缩进（`425/-142`）全部与学生卷 A 逐字一致，只有三处不同——卷别后插「答案」、客观题空括号里填了答案、主观题答题空白被换成参考答案要点；`pgSz/pgMar/docGrid` 也完全一致。

⇒ 规律：**卷面标注答案卷 = 学生卷 spec 的一次派生渲染**，只做「填空 + 替换空白 + 卷头加两字」。题干、选项、题号顺序零重敲，A/B 卷答案不会串位。实现上从同一份 `exam-spec-A.json` 生成，客观题答案从 `tmp-paper-A-objective.json` 同源读取，主观题答案从答案 Markdown 解析，禁止手抄。

### 11.3 七条生成规则

1. **卷头只改一处**：`【智能制造装备】课程（A 卷）【闭卷】` → `…（A 卷）答案【闭卷】`；学号/姓名/专业及班级栏、满分与考试时间说明、卷首得分表原样保留；`分数/得分` 两行继续留空（§3）。
2. **客观题答案就地填入题干已有括号**，不新增括号、不改全半角：`（B）`、`(ABC)`、`（×）`、`(√)`。括号形态沿用学生卷（学生卷本身全半角混用），改动面最小；多选答案按字母升序，判断题统一 `√/×`。
3. **主观题删掉全部答题空白（spacer），换成答案块**：题干后一个统一标签（建议 `参考答案与评分要点：`），标签 `keep_with_next` 绑定首条要点（§10.4-4），要点逐条独立成段。
4. **缩进对齐**：题号段 `283/-283`；小问 `（1）～（4）`、`①～⑤` 逐行 `425/-142`（§4.4）；**答案要点回到 `283/-283`，与题号段左对齐，不要再缩一层**，否则视觉上像「答案缩在题目里」。
5. **分值统一写法**：`【要点名】（N 分）` / `①…（N 分）` / `（1）…（N 分）`，整数、全角括号、数字与「分」间一个空格。**每道主观题各要点分值之和必须等于该题满分**（10 分题 2+2+2+2+2；15 分题 4+4+4+3），用脚本求和校验。§9.2 的整数门禁在这里升级成「合计门禁」。
6. **排版参数由生成器统一设定，不要混血**：学生卷题干/选项 `400 twips exact`（20pt）、字号继承模板；答案块统一 `18pt`（20pt 会多出一页孤页，见下）。§10 答案册正文是 `280 twips`（14pt）+ 10pt 直设。用户手改版把答案册内容粘进学生卷，导致卷面 20pt、答案要点 14pt 并存；复用时**所有答案块必须同为一个值**，不允许同类内容里出现两种行距。
   > 2026-11-24 B 卷实测：答案块 20pt 时成品 8 页、末页只有 1 条长要点（7 行）；统一收到 18pt 后为 7 页、末页 25 行，末页不再孤。长要点带 `keep_together` 时整段会被推到下一页，压缩行距比手改分页更可靠。
7. **页数靠「删空白换答案」抵消**：实测学生卷 A 与卷面标注答案卷都是 **7 页**。插入全部参考答案不必然扩页，因为答题空白被删掉了；不要为答案卷预留额外分页，派生 spec 合并成单页自然流动、0 硬分页。

### 11.4 手改留下的四类不一致，必须靠生成器消掉

| 项 | 手改版实况 | 规则 |
|---|---|---|
| 答案标签 | `答案：` / `参考答案` / ` 参考答案`（前导空格） | 全卷一个标签 |
| 分值格式 | `（2 分）` `（3分）` `（4分）` `表述 （1 分）` | 统一 `（N 分）`，且合计 = 满分 |
| 括号 | 全角 `（B）` 与半角 `(B)`、`(√)` 混用 | 客观题沿用原括号；**新增文字**统一全角 |
| 行距 | 卷面 400、答案要点 280 | 统一为学生卷 400 |

### 11.5 「人工另存」会破坏模板保真契约（重要）

用户版经**腾讯文档**另存：`docProps/app.xml` 的 `Application` 从 WPS 变成 `Tencent office`，`core.xml` 的 created/modified 刷新、`creator/lastModifiedBy/revision` 被清空，`docProps/thumbnail.wmf`（206 KB）与 `word/numbering.xml` 被整件删除，`styles/footer/fontTable/settings/footnotes/endnotes/theme` 全部重写，`pStyle` ID 从 `2/3` 变成 `000013/000014`，并显式写入大量 `keepNext/keepLines`。文件从 33 KB 降到 23.8 KB。

对该文件跑 `verify_docx.py` 得到 `valid: false` / `preserved_parts_mismatch`，**7 个保留部件全变**（6 个 changed + numbering missing）。

⇒ 规律：

- **区分「生成态」与「人工修订态」**：生成态才做 `verify_docx.py` 的 7 部件 byte-identical 校验；经任何编辑器（腾讯文档 / Word / WPS）打开保存过的文件一律**不再做保真校验**，改跑内容门禁（题号覆盖、答案同源、分值合计、AI 痕迹、PDF 逐页）。把另存版当模板 rebuild 会把样式 ID、页脚、keepNext 一起带跑。
- **AI 痕迹门禁要覆盖 `docProps/app.xml` 的 `Application` 字段**，不只看 core.xml 的 creator。
- **手改必须回流到 spec / 生成器**：用户改出来的新版式是需求变更，正确做法是把 §11.3 写进生成器后重建，而不是保留这份另存文件当模板（与 SKILL.md「Hand-edit the generated DOCX → Change the spec/generator and rebuild」一致）。
- 另存后 `keepNext/keepLines` 被大批量显式写入，分页可能变；交付前重新转 PDF 逐页复核。

## 12. 门禁与生成器的通用化（多课程复用，2026-11-24 复盘）

本节的每一条都来自一次真实的误报或返工。§11 的规则是通用的，但脚本第一版
按《智能制造装备》卷写死，换一门课就全红。结论：**规则可以定制，脚本必须自适应**。

### 12.1 门禁里禁止出现的硬编码

`verify_answer_keyed_paper.py` 初版写死了 18 道客观题、6 道主观题、
`FULL_MARKS=[10,10,10,10,15,15]`、`^[四五]、` 章节、425/-142 小问缩进、
只看 `（A/B 卷）`。拿 C&C++ 卷（25 客观 / 8 主观 / 六章 / 425 缩进 /
`（A 卷）`）验证时 5 项误报——卷面本身完全正确。已改为：

- 题目分类：扫题号行，题目范围内出现统一标签 → 主观题，否则客观题。
  不依赖题数、章节名或分值。
- 卷别：`（[A-Z] 卷）答案`，不限 A/B。
- 得分表：只要求有「题号」表头 + 「得分」行全空；**不要求满分行有值或 3 行**。
  《智能制造装备》《人工智能技术及应用》的得分表所有分数行都留空，
  这是符合规范的，不是缺陷。
- 小问缩进：取卷面首个小问的实际 twips 为期望值，只校验**一致性**。
- 全称匹配章节标题：`^[一二三四五六七八九十]、`，不用 `^[四五]、`。

### 12.2 分值解析必须兼容四种卷面写法

同一条要点在不同课程里有四种合法写法，门禁必须全认：

| 写法 | 样例 | 来源 |
|---|---|---|
| 分值前置 | `（3 分）输出：sum=10` | C&C++、人工智能 |
| 标题内嵌 | `【状态信号】（3 分）主轴负载电流…` | 智能制造装备 |
| 题号 + 分值 | `（1）（3 分）定位精度受…` | 智能制造装备 |
| 正文再说明 | `（2 分）理由：…（2 分）。` | 人工智能 |

取**段内第一处 `（N 分）`**。生成态前缀是空 / `【…】` / `（数字）`；人工
修订态位置更自由——`①知识库（2 分）：`、`（1）链路（4分）：`、`表述合理（1分）`
甚至落在长句末尾，门禁一律认段内第一处。调用方只在答案区内逐段取分值，
不会碰到题干满分，放宽前缀不会引入误判；写法是否规范由 `mark_format`
单独判，两条规则互不干扰（2026-11-24 A 卷手改版实战修正）。
正文里第二次出现的分值（如「每处 1 分」）是说明，不是第二条要点，不能当作
歧义报错。要点合计的校验来源按优先级回退：
①题干 `（N 分）` → ②章节标题「共 N 题，每题 M 分，共 K 分」（每题向上找自己
所属章） → ③得分表「满分」行总分。三者皆无才判无法校验。

### 12.3 答案块插入点：两大错位陷阱

从学生卷 DOCX 直接派生时，答案块的位置错一次就要整份返工：

1. **插在题干段紧后** → 答案跑到代码表格和 `(1)(2)` 小问**中间**，
   阅读顺序变成「题干 → 答案 → 代码 → 小问」。必须插在该题**全部内容之后**。
2. **插在「下一题题干之前的最后元素」后** → 若下一章标题夹在中间，
   章标题带 `keep_next`，LibreOffice 会把答案块排到**章标题之后**，
   视觉上变成「五、程序查错与测试题 → 答案 → 1、题干…」。
   遍历时遇到 `^[一二三四五六]、` 必须立即 `break`，章标题属于下一章。

收尾要求：标签段 `keep_with_next=True`，且文档顺序下一段就是分值要点；
每个要点 `keep_together=True`。否则标签会孤立在页尾（§10.4-4 同类）。

### 12.4 DOCX 直派生路径（学生卷已定稿、只有答案 Markdown 时）

§11.2 的主路径要求 paper-spec.json + objective.json + 答案 Markdown 三件输入。
但现实中学生卷常常**已经是定稿 DOCX**，重建 spec 成本高且会引入排版漂移。
此时用 `scripts/derive_answer_keyed_from_docx.py <student.docx> <answers.json> <out.docx>`：

- 在 DOCX body 层只做三改：卷头加「答案」、客观题填原括号、主观题插答案块；
  其余段落/表格/样式**逐字不动**，再 `bfs._restore_parts` 恢复模板 7 部件，
  `verify_docx.py` 保真天然通过——这是 "逐字一致" 最强的实现。
- `answers.json` 结构：`{"paper": "A 卷", "objective": {"一": [...], ...},
  "rubric": {"四": [[[分值, 文本], ...], ...], ...}}`。
  内容从答案 Markdown 解析得来；题数由数组长度决定，不写死 25/8。
- 构建即断言：章题数与卷面对不上、题干找不到空括号、主观题数不符 → 直接报错。

### 12.5 回归基线（改门禁/生成器后必须全跑）

任何对 §11 脚本的改动，都要用**至少四套结构不同的卷**交叉验证（含表格版式，见 §12.7） `valid: true`：

2. 智能制造装备：18 客观 / 6 主观 / 五章 / 标题内嵌 + 题号分值写法 /
   得分表全空 / 425-142 缩进；
3. 人工智能技术及应用：25 客观 / 9 主观 / 五章 / 分值前置 /
   正文二次分值说明 / 得分表全空。

实测基线：首轮三套均 15 项全绿；`derive_answer_keyed_from_docx.py` 重建的
C&C++ A 卷与课程专用脚本产出**结构完全一致**（128 个 body 元素、0 处标签错位、

### 12.7 表格版式学生卷（一大题一表、一行一题）的派生与门禁（2026-11-24 B 卷实战）

§12.4 的派生路径最初只认「题干在段落」的 A 型卷。B 卷学生卷是**表格版式**：
每个大题一张 1 列表格、每行一道题（题干与代码在同一单元格的段落里）。
三处缺口都真实踩到，已一并修入脚本：

1. **派生器客观题填空**：遍历 body 时，`tbl` 元素下逐行取 `cell.paragraphs`，
   在含空括号的段落填答；不能只处理 `w:p`。
2. **派生器主观题答案位置**：表格题必须把答案块插到**该题所在行单元格的末尾**
   （`cell.paragraphs[-1]` 之后），这样答案紧跟本题代码。若图省事把一张表所有
   题的答案都插在表后，会出现「第 4 题代码 → 第 1、2、3、4 题答案」的顺序错位，
   读者无法判断对应关系（实测踩坑，整份返工）。
3. **门禁题目识别**：`body_items` 要把表格内段落以 `cell-p` 纳入；题目切分
   仍以顶层 `w:p` 和 `tbl` 为准（表格整体作为一个复合 question，再按行展开），
   标签/分值要点/小问缩进则在 `p` + `cell-p` 上识别。
   一个表格含多道主观题时，按**统一标签数**展开主观题，每题范围到下一个标签前，
   满分按表内题号行顺序取；否则会把整章要点算到一道题上。

回归基线扩充为四套卷：C&C++ A（段落题）、C&C++ B（表格题）、智能制造装备、
人工智能技术及应用。四套均需 `verify_answer_keyed_paper.py valid: true`。
B 卷实测：25 客观填答、8 主观 28 个答案段、7 部件保真、9 页无孤页、
标签全部紧跟本题、四套卷回归全绿。

### 12.8 代码块完整性回归：片段必须补全为可编译程序（2026-11-24 C&C++ 卷实战）

用户在卷面上指出 `int level = 2; switch (level) {...}` 这一段「代码格式有问题」。
缩进、边框、行号都正常，真正的问题是：**这是一段裸语句片段**，既没有
`#include <stdio.h>`，也没有 `int main(void)` 和 `return 0;`——直接违反 §9.3
「必须是可编译、真实完整的 C 程序；不要只贴片段，不要顶头直接写语句」。
复核发现 A/B 卷各有 6 段同类片段（计算、分支、循环、数组、宏、结构体），
共 12 段。已全部补全，并用 `clang` 逐段编译执行，输出与答案速查表 12/12 一致。

**规则（交付门禁）**：凡是题干写「运行下列代码，输出结果是」的代码块，
必须是完整可编译程序。唯一例外：题干明确问「关于下面这个**函数**…」，
此时给出函数定义是题意本身，不算片段；查错与测试题中待改的病态程序同理。

**补全时保持输出不变的做法**：原样保留原有语句，只在外面套
`#include <stdio.h>` + `int main(void) {` + `return 0; }`，并把内部每行缩进 +4 空格；
`#define` / `struct` 定义放在 `main` 之前。补全后必须逐段编译比对输出，
不能凭肉眼判断。

**三个隐藏坑（都真实踩到并返工）**：

1. **DOCX 里的空行是单个空格**：渲染器把代码块空行写成 `" "`，
   直接拿 Markdown 的空行文本去匹配 DOCX 段落会匹配失败。匹配前先做
   `"\n".join(line.rstrip() for line in p.text.strip().splitlines())` 归一。
2. **python-docx 重存会破坏模板部件**：补丁式修改 DOCX 后 `verify_docx.py`
   报 `changed:word/footer1.xml / numbering.xml / styles.xml`。
   保存后必须调用 `build_from_spec._restore_parts(template, output)` 恢复 7 个保留部件；
   从学生卷派生的答案卷因派生脚本内部已恢复，不受影响。
3. **代码变长引发分页回归**：每段多 4 行后，A 卷第 8 题出现「代码在本页末、
   A/B/C/D 选项跑到下一页」。把 1×1 代码表的段落精确行距 12.5pt→12pt、
   段前 3pt→1pt、段后 4pt→2pt，问题消除且总页数不变。**改完代码必须重新渲染
   PDF 逐页检查选项是否还在同页**，不能只跑 DOCX 门禁。

**自检增补**：

- [ ] 所有「运行下列代码」代码块都通过编译，输出与答案一致
- [ ] 若以 DOCX 为基底打补丁，保存后已 `_restore_parts`，`verify_docx` 仍为 true
- [ ] 代码变长后重新渲染 PDF，确认题干/代码/选项未跨页分家

### 12.9 题干一律不加粗：子问题干加粗是高频返工点（2026-11-24 复盘）

教师指出应用题 `(1) 写出你会给 AI 助手的完整提示词……` 这类**子题干被加粗**，
而同题的题干主体不加粗，卷面粗细不一致。明确规则：**所有题目的题干都不加粗**，
包括 `(1)(2)(3)(4)` 子问题干、`一、` 大题下的小题干，学生卷和答案卷一视同仁。

**加粗只保留在这几类（不是题干）**：

- 卷头：学校名、`(A 卷)` / `(B 卷)`、`【闭卷】`、命题信息抬头
- 大题标题：`一、单项选择题（共 10 题……）` 等章节级标题
- 答案卷标签：`参考答案与评分要点：`、`T26 参考答案`、`评分：……`、表头行

**为什么生成器会加粗**：spec/数据里把子问题干写成 `{"type":"text","bold":true}`，
`build_code_exam.py` 的 `render_section` 与 `build_answer_docx.py` 把 `bold` 原样透传。
生成时务必让所有题干块 `bold` 缺省（False），只在标题/卷头/答案标签上显式加粗。

**已定稿 DOCX 的低成本修复**：不要重跑整卷生成（spec 多在临时目录且易引入新漂移），
用 `scripts/unbold_substems.py` 在原 DOCX 上打补丁：

```bash
python scripts/unbold_substems.py paper.docx answer_keyed.docx teacher_key.docx
# 卷头若有手改残留垃圾 run（如误入的「这个」），附带清理：
python scripts/unbold_substems.py --drop-junk teacher_key.docx
```

判定规则精准：段落文本（strip 后）匹配 `^[\(（]\s*\d+\s*[\)）]` 才去加粗，
覆盖正文段落与表格单元格段落，不会误伤标题/卷头/答案标签/表头。

**保真要点**：脚本在修改前读取**文档自身**的 7 个保真部件、保存后原样写回；
不要用 `reference.docx` 覆盖——教师答案册可能是人工另存过的版本，部件与模板不同
（本次 A 卷教师册 7 个部件全部与模板不一致），用模板恢复会破坏其页脚/样式。

**修复后必须**：(1) 重新扫描确认「子题干仍加粗=0、大题标题加粗数不变」；
(2) 与备份逐段比对纯文本，差异只允许是明确清理的垃圾字符；(3) 重转 PDF 逐页目视
确认题干粗细一致、代码/选项未受影响；(4) 跑 `check_code_completeness.py` 回归。

**自检增补**：

- [ ] 所有题干（含 `(1)(2)(3)(4)` 子题）均不加粗；卷头/大题标题/答案标签/表头仍加粗
- [ ] 修复后纯文本与备份逐段一致（垃圾字符清理除外）
- [ ] PDF 重新渲染，目视确认题干粗细一致、无跨页分家

### 12.10 人工修订态的两个门禁误判防线（2026-11-24 A 卷实战）

同一份手改答案卷跑 §11 门禁时，曾出现两类**卷面本身正确、门禁误报**：

1. **裸标签导致「客观题未填答」误报**。§12.1 用「题目范围内是否出现统一
   标签 `参考答案与评分要点：`」区分主/客观题；人工修订态用的是裸标签
   `答案：` / `参考答案`，于是 6 道主观题全被算成客观题，`objective_answers`
   报 24 题未填答、`mark_sum` 报合计 0。修法：分类时 `BARE_LABELS` 也算
   主观题标记，但标签是否统一仍由 `rubric_labels` 如实报错。
2. **分值落在标签后/句中导致缺分误报**。见 §12.2，段内第一处 `（N 分）`
   通吃，不再限制前缀形态。

**判读原则**：门禁报「未填答 / 分值合计 0」时，先抽查卷面原文再下结论；
若题干括号里已有 `（B）`/`（ABC）`/`（×）`，或每条要点后面确实带分值，
那是门禁解析能力不足，应当修门禁，不要去改用户文件。

回归用例已固化在 `tests/test_answer_keyed_paper.py::GateRobustnessTests`：
覆盖六种分值前缀 + 裸标签分类 + 分值合计不变。

### 12.11 答案 Markdown 是自然语言评分要点时用 `--marks-json`

同一门课的 A/B 卷，答案 Markdown 的「评分要点」可能风格完全不同：B 卷是
结构化 `(1) 4 分：…`，`parse_marks()` 能自动拆出各要点分值；A 卷是自然语言
「成因：翘曲 2 分、拉丝 2 分（各≥3 点）；措施：两类各 2 分……追溯记录 2 分」，
正则拆出的数量与要点数对不上，生成器抛 `分值解析失败…请用 --marks-json
显式提供`。

**这不是数据错误，不要改答案 Markdown 去迁就解析器**。按评分要点原文手工
核定每题分值向量，写成 JSON 用 `--marks-json` 传给
`build_answer_keyed_paper.py`，并把这份 JSON 作为**派生数据**与 spec 一起
保存在 `.workbuddy/`，保证下次可复现：

```bash
python scripts/build_answer_keyed_paper.py exam-spec-A.json objective.json \
  answer.md answer-keyed.docx --marks-json marks.json --spec-out keyed-spec.json
```

`marks.json` 的 key 是「题型简称 + 题号」（如 `简答1`、`综合2`），value 是
与要点一一对应的整数数组，**每题各值之和必须等于该题满分**，生成器会再
校验一次。例：10 分 5 要点 `[2,2,2,2,2]`、10 分 3 要点 `3+3+4`、
15 分 4 要点 `[4,4,4,3]`。

## 13. 卷内内容质量门禁（2026-11-24 新增）

**来源**：《人工智能技术及应用》A 卷复盘。该卷排版、答案卷结构、A/B 查重全部通过，
但 25 道客观题与 9 道主观题大面积考同一批术语：单选的正确选项直接写进简答/应用答案，
学生做前面题就等于拿到后面题的答案。§5 的“无答案泄漏关键词”只查学生卷里有没有印
`参考答案` 字样，§8 只查 A/B 两卷之间，两者都挡不住这种**卷内前后泄题**。

### 13.1 必跑命令（构建 DOCX 之前）

```bash
python scripts/check_paper_content.py exam-spec.json objective.json answer.md \
  --blueprint blueprint.json --md-out content-report.md
```

`blueprint.json` 为本课程单元 → 关键词映射：

```json
{"units": [
  {"id": "U1", "name": "人工智能基础", "keywords": ["图灵", "三大流派"]},
  {"id": "U2", "name": "机器学习", "keywords": ["监督学习", "K-means"]}
]}
```

退出码 1 表示存在 error 级问题，**不得继续构建 DOCX**；warning 也要逐条确认。

### 13.2 检查项

| 检查 | 判定 | 处理 |
|---|---|---|
| 卷内重复 | 题干整句相同或连续考点片段（≥4 字）高度重合 | 合并为一题，或把其中一题换成不同考点 |
| 前后泄题 | 客观题“题干 + 正确选项”与后面主观题“题干 + 答案 + 评分要点”连续片段重合 ≥0.25 | 改写前题结论性选项；或换掉后题考点/情境 |
| 覆盖缺口 | blueprint 中某单元关键词在卷面与答案中一个都没出现 | 在重复/泄题题位补该单元的新题 |
| 题干不清 | 主观题用未定义的口号式代称（如“改造已有样本”“借用已有能力”）或“上述/这两条”等无先行词指代，并要求说明/比较 | 改成标准术语（数据增强、迁移学习/微调等）或在题干内先给定义、例子和作答维度 |

脚本按“连续相同片段的长度”加权，片段越长权重越高；`图灵测试`、`降低特征图尺寸`、
`事实幻觉` 这类考点指纹能抓到，而“的主要作用是”这种句式套话可被忽略。

### 13.3 两种绝对不能干的事

1. **只看排版门禁就交付**——`verify_docx.py` valid 只能证明模板没坏，证明不了题目没毛病。
2. **把前题答案原句搬到后题答案里**——同一卷里这叫送分，不叫“知识点复现”。
   客观题可以考概念识别，主观题就必须换成**不同角度**：考流程、辨析、选型、评价、迁移应用，
   而不是让主观题去复述客观题的正确选项。

### 13.4 自检增补

- [ ] `check_paper_content.py` 退出码 0（或所有 warning 已人工确认）
- [ ] 题干清晰性 0 条 error；所有口号式代称已改为标准术语或已在题干内定义
- [ ] 参考答案逐条对应题干实际提问，没有题目未问的“好处/意义/背景”分点
- [ ] blueprint 全部单元有覆盖，没有“某单元 0 题”
- [ ] 内容报告留档，逐条列出处理动作（改哪题、换成什么考点）
- [ ] 改完题目后重新跑本门禁 + §8 A/B 查重 + §5 渲染验收

### 13.5 这类问题应在哪一阶段反思

题干“根本没说清”不是排版问题，不能等到 DOCX/PDF 阶段再发现。正确检查点是：

1. **命题草稿 / paper-detail alignment draft 阶段**：逐题自问“不看答案册，考生能否知道要答什么？引号里是自造口号还是标准术语？适用条件/比较维度是否明确？参考答案是否逐条对应题干实际提问，而不是给题目没问的好处/意义另设分点？”——这是第一道、也是最有效的反思点。
2. **构建 DOCX 之前**：跑 `check_paper_content.py`，让“题干不清”和重复/泄题/覆盖缺口一起阻断构建；error 未清零不得进入 `build_from_spec.py`。
3. **PDF 渲染阶段**：只检查分页、截断、错位，不负责判断题意是否清楚。若到这里才发现题干不清，说明前两道门禁失守，必须回到 spec 改题并重建，而不是手改 DOCX。

### 13.6 客观题与主观题「同一热点」的前后泄题：优先改客观题措辞（2026-11-24 实战）

把大语言模型 / 数字孪生 / 智能诊断等热点同时出成客观题和主观题时，极易出现
**客观题正确选项把后面主观题的评分要点先说出来**。实测一套卷修前 A 卷 6 处、
B 卷 1 处 error 级泄题，例如单选正确选项写「双向实时映射、同步演化」，而简答
正要求「说明数字孪生与离线仿真的区别」；判断题干写「孪生模型需校准与版本管理」，
而简答正要求「说明校准与版本管理的必要性」。

**最小改动原则：先改客观题的正确选项 / 题干措辞，不动主观题。** 理由：

- 主观题是 10 / 15 分大题，题干、小问、评分要点、分值向量是一体的，改一处要
  连带重建答案册、标注答案卷、对照表，牵动面大；
- 客观题只需把正确选项**再抽象一层**——保留考点判定能力，但不出现主观题评分
  要点的原词。例：「双向实时映射、同步演化、反向优化实体」→「随实测数据持续
  同步、能把分析结论反哺现场运行的活模型」；「迁移学习/小样本学习+跨工况测试」
  →「借用相近工况已学得的表示、少量标注微调、独立工况检验」；
- **答案字母、分值结构、答案册 Markdown 全部不用动**，只需同步改
  `objective.json` 与 `exam-spec.json` 里对应的 `question` / `option` 块，再
  重建学生卷与标注答案卷即可。主观题情境是第二选择，仅在客观题怎么改都仍
  重合时才动。

**执行纪律**：

1. 改前先备份 `exam-spec-*.json` + `tmp-paper-*-objective.json` 到
   `.workbuddy/backup/`；脚本按「客观题序号」定位时，**判断题的序号 = 13+i**
   （单选 1-8、多选 9-12、判断 13-18），极易把判断 1 误当判断 2，改完必须
   逐题打印题干核对。
2. shell 循环里用 `${L}` 而不是 `$L卷`——中文会粘进变量名，导致输出路径
   少了卷别、`check_paper_content.py` 找不到答案册。
3. 改完先跑 `check_paper_content.py --json-out ... --md-out ...`，看
   `leakage` 里 `severity=error` 是否清零；再跑全量保真 / 15 项门禁 / PDF。
4. error 清零后 `passed` 仍可能为 `false`，因为 warning 级（共享术语、
   `npm` 重合度 0.3 左右）会保留。warning 属「人工复核」级别，逐条看过确认
   不是换汤不换药即可接受，不必强行清零。

实战结果：A 卷泄题 11→6（error 6→0）、B 卷 5→4（error 1→0），两卷
`passed: true`；A/B 学生卷、标注答案卷、教师答案册、对照表共 7 份全部
`verify_docx.py valid:true`，两份标注答案卷 15/15，PDF 逐页无孤立元素。

### 13.7 程序类试卷跑内容门禁：三类误报与「是否重出」的判定（2026-11-24 C&C++ 卷复盘）

更新后的内容门禁（§13）在《人工智能技术及应用》这类**文字概念卷**上很有效，
但直接套到**程序代码卷**（C&C++）会报出一堆 `error`，须人工判定性质，
不能见 error 就重出整套卷。本次对一套已定稿 A/B 卷的完整核对：
模板保真 4/4 true、代码完整 6/6、题干零加粗、A/B 查重通过、清晰性 0、
单元覆盖 0 缺口；`check_paper_content.py` 却报 A 卷 4 条、B 卷 2 条 error。
逐条判定后**无需重出**，六条全部是误报或命题设计选择。

**三类典型误报（务必识别，不要据此改卷）**：

1. **代码语法骨架**：判断题题干 `for (i = 1; i <= 10; i++)` 与查错题代码里的
   `for (...)` 被判"泄题"，重合片段是 `fori=1i<` 这种语法骨架。
   门禁的中文 4-gram 对代码 token 无语义概念，只要字形像就高分。
2. **场景名/项目名**：多选"俄罗斯方块函数拆分"与应用题"俄罗斯方块查错"
   仅共享场景词，考点完全不同（模块划分 vs 边界越界），却被判 error。
3. **通用术语**："测试用例""用 scanf 读""非法输入重输"是本课高频术语，
   在多题自然复现，不是某题把某题答案先说了。

**一类边界项（命题设计选择，可不改）**：
同一作业素材（如 A4 猜数字、A6 石头剪刀布）既出客观题考"实现要考虑什么"，
又出应用题考"给它写 AI 提示词/协作方案"——客观题的**题干**复述了应用题
的**评分要点**（随机 1~100、太大/太小、非法重输）。这是"同素材跨题型复现"，
不同于 §13.6 的"客观题正确选项直接抄主观题答案"：学生做前面题只是读到需求，
并未拿到后面题的答案文本。若教师要求绝对隔离，可把客观题选项再抽象一层，
属可选优化，非硬错误。

**"是否重出"的判定流程（先判性质，再动手）**：

1. 先跑所有**硬门禁**：`verify_docx.py` 保真、`verify_answer_keyed_paper.py`
   结构、`check_code_completeness.py`、题干加粗扫描、§8 A/B 查重、§12.9。
   这些过不了才必须重出/重建。
2. 再跑 `check_paper_content.py`，对每条 error 看 `evidence` 的"重合片段"：
   是**结论性答案原句**（真泄题，按 §13.6 改）还是**代码/场景/术语骨架**
   （误报，记录理由后放行）。
3. 只有"硬门禁失败"或"确认是真泄题"才重出；仅内容门禁误报不构成重出理由。

**另一个已知门禁局限**：`verify_answer_keyed_paper.py` 的 `mark_sum` 会把
要点段落里**嵌套的小分值**也累加。例如应用题要点写成
`（8 分）…①各 1 分；②1 分…` + `（7 分）指出问题（3 分，每处 1 分）…`，
15 分题会被算成 8+7+3+…=45。把评分要点做成**表格**（分值单列）或确保
每个要点段只有一个"（N 分）"即可规避。判定方法：直接读 DOCX 该题各段，
人工核对 8+7=15 正确，即确认是门禁解析偏差、不是文档错误。

**自检增补**：

- [ ] 内容门禁 error 已逐条判定性质，误报已记录理由，不盲目改卷
- [ ] 判定"不重出"前，全部硬门禁（保真/结构/代码/题干/查重）均为 true
- [ ] `mark_sum` 报分时先读原文核对，区分门禁解析偏差与真实分值错误
